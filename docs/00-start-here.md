# Start Here

Welcome in. This is the page you open when you first sit down. The goal is not to prove that you already know everything. The goal is to get oriented, run the course, and build one small piece of confidence.

## What this repo is

This repository is your workshop cockpit. It contains:

- the course book you are reading now,
- a small example API you can run locally,
- labs that walk you through terminal, Git, AI prompts, testing, and review,
- templates for AI coding tools,
- checklists you can reuse in your own projects.

If you feel lost at any point, come back to this page and restart from the latest step you completed.

## The first commands

Open Terminal, then run:

```bash
git clone https://github.com/thetechhustle/ai_workshop_linkedin2026.git
cd ai_workshop_linkedin2026
make install
make test
make run
```

What each command means:

| Command | Plain-English meaning |
|---|---|
| `git clone ...` | Download a copy of the workshop repo to your laptop. |
| `cd ai_workshop_linkedin2026` | Move your terminal into the repo folder. |
| `make install` | Create the Python environment and install project tools. |
| `make test` | Check that the example app works on your machine. |
| `make run` | Start this workshop book locally. |

`make run` starts the workshop book. Open <http://127.0.0.1:8001>.

## Starting the example app

When it is time to work with the API, open a second terminal tab and run:

```bash
make startapp
```

You can also use the alias:

```bash
make example-app
```

Then open <http://127.0.0.1:8000/docs>. That page is generated by FastAPI and lets you test the API in your browser.

## What success looks like

You do not need to finish every stretch goal. Pick the level that matches where you are today.

| Level | Success looks like |
|---|---|
| **Bronze** | I cloned the repo, opened the workshop book, ran the app, and can explain what the app does. |
| **Silver** | I made one small change, inspected the diff, and ran a quality check. |
| **Gold** | I improved a test, checklist, Docker note, GitHub workflow, or production-readiness explanation. |

Bronze is not small. Bronze means you showed up, used the terminal, and got a real project running.

## The rules of the room

- Ask questions early.
- Copy commands carefully.
- Do not paste private keys, access tokens, passwords, or private student data into AI tools.
- Do not let AI edit a project before you understand the plan.
- Treat every error message as evidence, not as a personal failure.
- Keep your changes small enough that you can explain them.

## If something breaks

Use this reset checklist:

```bash
pwd
git status
make help
make test
```

Then ask for help with three pieces of information:

1. What command did you run?
2. What error did you see?
3. What did you expect to happen?

That is how engineers debug. Not by guessing. By collecting evidence.
